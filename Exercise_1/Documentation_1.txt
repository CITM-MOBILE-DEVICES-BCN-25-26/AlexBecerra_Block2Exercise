Which SOLID principles are being violated?
1. Single Responsibility Principle
2. Open/Close Principle

 Where in the design the problem occurs
SRP: la clase matchSummary tiene demasiadas responsabilidades/ se encarga de hacer demasiadas cosas (guardar datos, calcular performance, printear summary y exportar resultados)
OCP: Cada vez que quieras añadir un nuevo método de export has de modificar la clase original matchSummary

Justification
matchSummary ahora es la clase matchData, que solo almacena información.
Las variables pasan a ser propiedades para que no puedan ser modificadas.
Nueva clase PerformanceCalculator con la función GetPerformance
Nueva clase Printer con la función BuildSummaryText
Nueva interfaz IMatchExporter con la función Export
Nuevas clases JsonExporter y XmlExporter que heredan de IMatchExporter


SRP: Ahora cada clase tiene su propia responsabilidad
OCP: Al tener una interfaz IMatchExporter, para añadir más métodos de exportación solo sería necesario crear una nueva clase que herede de IMatchExporter
